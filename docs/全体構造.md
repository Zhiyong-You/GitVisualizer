## 全体構造

VS 2022/2026 向けの Git クライアント拡張(VSIX)のスケルトン。依存の向きは一方向。

```
Vsix ──► UI ──► Core ◄── Core.Tests
  └─(exe を同梱するだけ)─► GitEditorHelper
```

| プロジェクト | 役割 | 状態 |
|---|---|---|
| **GitVisualizer.Core** (net472, VS/WPF 非依存) | git.exe を起動して結果を解析し、ドメインモデルとして返す | インターフェースとモデルは完成済み。実装はすべて `NotImplementedException` |
| **GitVisualizer.UI** (WPF + CommunityToolkit.Mvvm) | ViewModel と XAML。VS の型は XAML のテーマキー参照にだけ使う | 画面はダミーデータで表示される。コマンドの中身は TODO |
| **GitVisualizer.Vsix** (旧形式 csproj) | Package / ToolWindow / メニュー、VS 固有サービス(ダイアログ、通知、出力、ソリューションのリポジトリ検出) | ほぼ完成済み。手動 DI は `GitVisualizerPackage.InitializeToolWindowAsync` |
| **GitEditorHelper** (exe) | reword 用に `GIT_SEQUENCE_EDITOR` / `GIT_EDITOR` として git から呼ばれる | TODO |
| **GitVisualizer.Core.Tests** (xUnit) | 現在は `GitResultTests` の 1 件のみ | — |

## Core の内部構成

```
Infrastructure/  GitExeLocator → GitProcessRunner (IGitCommandRunner) … git.exe の起動
                 GitOutputParser   … for-each-ref / log -z / status v2 / 進捗行の解析
                 RepositoryWatcher … .git を FileSystemWatcher で監視
Services/        Branch / History / Commit / Sync / RepositoryState
                 (runner で git を実行 → parser で解析 → Models を返す)
Graph/           CommitGraphBuilder … CommitInfo 一覧からレーン配置を計算(純粋ロジック)
Models/          CommitInfo, BranchInfo, FileChange, 各種 Options, GitResult など
```

各 TODO コメントに、実行する git コマンドと引数がほぼそのまま書かれている。設計は固まっており、中身を埋める段階。
