# 実装メモ

調査日: 2026-09-29(コミット `355244f` 時点)


## 着手順(Core のボトムアップを推奨)

UI から始めると、どのボタンを実装しても `GitProcessRunner.RunAsync` の `NotImplementedException` に当たって先に進めない。`VsSolutionRepositoryLocator` もこの runner を使うため、リポジトリの検出すら動かない。Core は VS なしで `dotnet test` だけで確認できるので、F5(実験用インスタンス)は UI の配線段階からで十分。

1. **`GitOutputParser` + テスト**
   入力が文字列で出力がモデルの純粋関数なので、最初に取り組むのに最適。実際の `git log -z ...` などの出力をテストデータとして使う。
2. **`GitExeLocator` → `GitProcessRunner`**
   全機能の土台。UTF-8 リダイレクト、stderr の進捗行、キャンセル時の Kill を扱う。一時ディレクトリで `git init` する結合テストを 1 本書いておく。
3. **縦に 1 本通す(ブランチ一覧)**
   `BranchService.GetBranchesAsync` → `BranchTreeViewModel` の Refresh → `MainViewModel` の Refresh(`IRepositoryLocator` でパスを決める)。
   ここで初めて F5 を押し、実データが表示されることを確認する。
4. **履歴 + グラフ**
   `HistoryService.GetLogAsync` → `CommitGraphBuilder`(テストで検証しやすいロジック)→ `CommitGraphCell` の描画。
5. **ステータス / コミット、Fetch / Pull / Push、ダイアログ系**
6. **Rebase / Cherry-pick / Reword / Continue / Skip / Abort と `GitEditorHelper`**
   途中の状態を扱うため、一番難しい部分。最後に取り組む。

UI 側(ダイアログの ViewModel のプロパティ定義など)は Core と並行して進めてもよい。ただし「動くもの」を早く見るなら 1 → 2 → 3 が最短。

## 気づいた点

- **`.gitignore` がない。** そのため `bin/`、`obj/`、`.vs/` が untracked として出ている。Visual Studio 用の `.gitignore` を追加する。
- **`.github/copilot-instructions.md` の中身は Azure 用のルールだけ。** このプロジェクトとは関係ないので、意図したものか確認する。
